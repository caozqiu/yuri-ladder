# 尤复天梯观察站：免费托管版

目标平台：腾讯云 EdgeOne Makers / Pages 免费托管，自有域名单独按年购买。
本目录是独立迁移项目，旧 chatgpt.site 网站保持原样。初始数据为两个完整赛季，各100人；统计完全排除流局、无效局。

## 本地运行

需要 Node.js 22.22.3（最低22.13）。

```sh
npm ci
npm run build
npm test
npm run preview
```

打开 http://127.0.0.1:5188/ 。天梯接口只读，无采集入口；赞助赛预览使用隔离的本地文件存储。
dist 是公开前端及函数源码。完整发布使用 node scripts/deploy.mjs，由官方CLI编译为 dist/.edgeone 后部署；直接上传原始dist仅能保证静态页面。collector 中的采集程序、状态文件不在公开产物中。CLI会将项目环境变量嵌入服务端编译文件，因此原始dist/.edgeone只能作为私有部署材料，不能直接公开分享；自动流程生成的下载备用包已清空审核密码，社区申请和审核默认关闭，需使用源码经现有Actions重新编译部署才能启用。线上正式站使用有私密配置的服务端版本，下载包的处理不影响线上启用状态。

## 一次性配置

1. 将源码上传自己的 GitHub 仓库，默认分支 main。若选公开仓库，标准 GitHub 托管运行器免费；源码、玩家公开战绩和同步进度会对外可见。私有仓库需控制免费分钟数。不要向仓库提交账号、Cookie、Token或其他凭据。
2. 腾讯云账户开通 EdgeOne Makers / Pages 免费版，创建或复用一个项目，项目名建议 yuri-ladder。选择「全球可用区（不含中国大陆）」，无备案域名只能用这一加速区域。CLI 的 --site china 是腾讯云中国站账户选择，与加速区域不同。
3. 在 EdgeOne 控制台创建 API Token。在 GitHub Settings → Secrets and variables → Actions 中保存为 EDGEONE_API_TOKEN。凭据只放 Secrets，不要发到聊天或写入源码。
4. 发布固定核对现有项目ID makers-i6sbocft2osz，通过官方SDK读取实际项目名与加速区域，再调用CLI发布；不依赖猜测的项目名。EDGEONE_SITE 为 china，国际站账户则用 global。SDK只用于核对已有项目，不创建项目或修改凭据。
5. Actions 中手动执行 Hourly ladder sync and deploy，代码首次推送也会启动。它会恢复进度、采集、保存进度、构建、测试，并部署同一个项目。没有 Token 时仍执行数据更新和测试，生成上传产物，跳过网站部署并注明待配置。
6. 已选择自有域名 yuri-ladder.cn，用户已购买且已通过审核。审核通过后绑定现有项目，无需再购买云服务器。
7. 在项目「域名管理」绑定实际购买的域名。将平台实际返回的CNAME写入DNS；不可预先猜CNAME。申请免费HTTPS证书，待域名和证书状态均正常再分享。
8. 从国内手机流量和家庭宽带分别关闭代理测试首页、筛选、选手详情和比赛明细，通过后才确认国内直连可用。

不建议提前为域名支付多年费用。平台默认域名在中国大陆要求3小时有效的预览链接，自有域名绑定完成后才适合长期分享。免费托管和自有域名不能保证每个国内运营商的跨境线路质量。

## 每小时采集和断点恢复

工作流在北京时间每小时第17分钟触发（UTC同为17分），也支持手动运行。GitHub调度可能延迟。每次最多采集45分钟，任务总限时60分钟，为保存进度、构建、验收和发布预留时间。未结束时保存翻页游标，下次从原处继续；不会发布半成品排名。2026-10-22为全榜首次历史补采延长单轮预算并调整调度分钟，避免把触发间隔拉长后进一步拖慢补采；完成后仍逐次扫描所有在榜选手，按原有48小时回查规则做增量更新。已经开始的运行沿用启动时的配置，不取消正在采集的任务。

SQLite仅在每次运行器内使用。同步状态导出为带SHA256校验的NDJSON，写入同仓库独立 ladder-data 分支；下一台运行器从该分支重建数据库，包括翻页游标、待查摘要、完整和暂存批次。公开页面只读取已经完整的内容文件。采集失败仍可部署上次完整数据并显示失败进度。

仓库主分支放代码；ladder-data分支放采集状态和公开快照。工作流只推送数据分支，不覆盖主分支。全程并发不超过2、全局请求间隔至少2秒；遇来源限流立即保存进度，下个周期重试。比赛ID字符串、双人gameType=4且gameVersion=0；每7天完整复核，新入榜选手补历史，旧选手回查48小时。

`npm run sync` 是完整同步命令。`node collector/collector.mjs step` 只推进一批，退出码75表示已保存的未完成任务；退出码1表示失败。退出码0为完成或只导出。设置 YURI_CHECKPOINT_DIR、YURI_DATA_DIR、YURI_PUBLIC_DATA_DIR 可隔离工作目录。生产不要同时运行两个独立采集器。

公开仓库若长期无活动，GitHub可能停用定时工作流；检查Actions状态并按需恢复。数据分支持续更新也需关注平台策略变化。不要把免费定时调度视作精确到分钟的服务承诺。

## 普通用户账号、昵称与头像

入口：https://yuri-ladder.cn/?screen=account 。访客可注册普通账号，填写昵称和至少10字符、UTF-8不超过72字节的密码，系统生成YR开头的专属登录账号；昵称允许重复且可以修改。账号使用随机恢复码派生的96位标识，不依赖Blob不支持的条件覆盖写来抢占唯一用户名。请保存账号与恢复码；恢复码可重置密码，无需提供邮箱。本功能不使用兰博平台的账号密码。

个人中心支持登录、退出、修改密码、恢复密码、修改昵称、上传或移除头像。浏览器将5MB以内的PNG/JPEG/WebP图片居中裁为400像素正方形JPEG，服务端核验图片类型、尺寸与256KB限制，拒绝SVG等主动内容。公开资料只返回账号、昵称、头像URL和创建时间，不公开密码散列、盐、恢复码散列或会话记录。

密码使用bcrypt、成本参数10和每用户独立随机盐保存，恢复码与随机会话令牌只保存SHA256散列。登录使用30天HttpOnly、Secure、SameSite=Strict的独立用户Cookie；退出撤销当前会话，修改/恢复密码令旧会话全部失效。普通用户与站主审核账号完全分离；站主更换审核密码不影响已有普通用户会话。注册恢复码在浏览器临时会话中保留到用户确认已保存，不保存登录密码。

账号资料持久化到现有EdgeOne项目的私有Blob命名空间yuri-user-accounts，不随每小时静态发布覆盖。登录后新提交的办赛、报名、赞助赛记录由服务端关联账号；个人中心跨设备读取对应记录与报名名单，不需要再粘贴回执。归属不能通过请求中的ownerId伪造。过去匿名提交的记录继续使用原回执，不会按同名昵称自动认领。公开赛事可直接查看；发起赛事、报名、登记赞助赛和导入对局均须登录普通账号，服务端强制校验。旧匿名记录继续凭原回执查询。

API：GET /api/account?action=session|challenge|profile|avatar；公开profile/avatar要求id，POST action=register|login|logout|profile|password|recover。GET /api/sponsors?action=mine及/api/events?action=mine只返回当前登录账号关联的记录；receipt/manage/entry继续支持旧回执，并额外允许对应关联账号本人读取。账号路由同样要求同源JSON、正文大小限制和尽力限流。

新增9项账号及关联权限测试。verify-accounts.mjs在独立私有命名空间验证注册、刷新实例登录、头像昵称持久化、资料隐私、关联记录与恢复/退出；日常正式站检查只核对开放状态、匿名拒绝与不存在账号的密码校验，不创建正式站测试账号。所有者另行授权的一次性验收由verify-live-account.mjs完成，仅在推送标记[verify-member-once]的首次运行时创建1个临时普通账号，验证真实注册、登录、昵称、头像及会话后，核对恢复码散列身份，仅清理该账号与已知会话、头像和资料，不创建赛事；每小时任务不会执行此生产写入测试。

## 赛事创办与报名

公开入口：https://yuri-ladder.cn/?screen=events 。所有访客注册并登录后可申请办赛，必填赛事名称、发起人、赛制、赛事介绍与规则、报名开始、报名截止和比赛开始时间，公开联系说明可选。日期统一按北京时间输入；截止须晚于开放时间，并且不晚于比赛开始时间。新申请的报名截止须在将来。只有站主审核通过后，赛事才出现在赛事广场并允许报名；按时间自动呈现未开放、报名中、截止和已开始，无需后台定时任务切换。撤回公开后拒绝新报名，已有报名资料保留供发起人处理。

报名者须先登录，必填圈内报名昵称、LBW平台昵称和5–12位QQ号，备注可选。QQ号仅发起人与站主可见，旧报名的联系方式继续保留。新报名按赛事及LBW平台昵称检查重复，兼容旧版数字ID回执，提交重试不覆盖已有资料；并发竞争可能留下多个原始提交记录，新记录按LBW平台昵称去重，旧记录仍按数字ID去重。平台昵称由本人填写，不代表平台账号认证，发起人可进一步核对。开放时刻包含，截止时刻不包含；服务端核对窗口和最新审核状态，不依赖浏览器时间或隐藏按钮。

发起人使用管理回执在“我的赛事与报名”查看审核结果、报名人数、名单和联系方式；回执可自行复制后在其他设备粘贴。报名者另有自己的报名回执，只能查询自己的报名。回执在请求前保留，网络失败时先查询确认是否收到；不要公开回执。浏览器会保留最多30条各类回执，不在地址栏传递密钥。报名联系方式不放在公共页面、公共列表或公开接口中，仅发起人与站主可见。公开赛事仅有聚合人数。

资料保存在同一现有项目的私有Blob中，以events、event-states、event-reviews和event-entries前缀分开，天梯更新不会覆盖。报名名单按每页30条加载；页面人数由独立报名对象去重计算，存储列举有短暂传播延迟，发起人可刷新人数与名单，不采用易丢更新的共享自增JSON。极大规模（一次扫描5000条以上）将显示人数下界并带加号。公开赛事每页12场；搜索作用于已加载赛事。

站主账号与赞助赛共用 SPONSOR_ADMIN_PASSWORD，使用/api作用域的HttpOnly会话。旧版会话需重新登录，密码不变。办赛审核支持通过、驳回和撤回；原因向发起人显示。管理/报名回执只在服务端比对散列，限流及同源JSON防护沿用赞助赛。无需另建云服务器或额外账号。

API：GET /api/events?action=list|session|challenge|queue；详情加id，queue仅站主；POST action=create|manage|review|join|entry。manage必须提供管理回执，entry必须提供自己的报名回执。网址使用screen=events、eventTab=create/mine/review、eventId恢复公开赛事详情。赛事广场卡片、公开详情、发起人管理页及个人中心的赛事名单窗口提供“复制报名链接”。创建后自动打开本场管理资料，待审核时可先复制地址；审核通过后地址可公开访问。链接仅包含screen=events、eventId和eventAction=join，不带管理回执或报名联系方式。访客打开会直接定位报名入口；先登录并自动返回，注册者须先确认保存恢复资料。未审核、被撤回、未开放、已截止或已开始的赛事不能报名。eventAction和returnTo不影响天梯统计。

新增7项赛事测试，覆盖时间边界、审核前隐藏和禁止报名、公开隐私、发起人权限、重复/重试、重启保留、撤回及未登录拒审。部署后在独立私有验收命名空间核对办赛→审核→报名→发起人读取人数及名单，正式站只核对公开接口和拒审，不自动发布虚假赛事。当前不包含收费、自动分组、对阵编排或平台账号归属认证。

## 赞助赛登记、平台对局导入与站主审核

公开入口：https://yuri-ladder.cn/?screen=sponsors 。访客须先登录观察站普通账号，才能登记或导入对局；不需要提供兰博账号密码。必填双方昵称、北京时间的对战时间与最终比分；赞助者、赛事回放视频网址和逐局地图/胜方可选。回放支持完整http/https视频链接，拒绝脚本、文件及含用户名密码的地址；审核后在卡片和详情中显示外部观看链接，不上传视频文件或由服务器抓取视频。允许部分逐局资料，逐局胜场不能超过最终比分。赞助赛独立于官方天梯统计，不计入天梯矩阵与胜率。

上方填写圈内常用昵称，下方填写LBW平台昵称；手动登记无需数字ID。按平台昵称与对局编号自动匹配双方，内部保留稳定ID用于校验，同名或昵称不符时拒绝猜测。粘贴对局编号（每行一个、单批最多30个），逐个读取公开比赛摘要，核对双方ID、尤复版本、双人真人、已结束且一胜一负；不要求是天梯模式，因此普通房间赞助赛也可登记。排除流局、无效局、原版、非双人或参与者不符的记录。比赛编号全程为字符串，保留大整数。自动填入原始地图、国家、胜方和时间；平台昵称使用该局来源昵称，圈内常用昵称保持独立，首批导入可汇总比分，后续支持按逐局胜负重新汇总。部分导入不推断遗漏场次，最终比分仍由申请人核对。单申请禁止重复编号。

已导入对局的地图与结果不可直接编辑，修改平台昵称前需先删除导入记录；服务端使用HMAC校验导入数据，篡改地图、胜方或平台绑定会拒绝提交。平台ID关联只是核对本场参赛双方，不是平台账号归属认证。逐局可分别选双方国家（美国、韩国、法国、德国、英国、利比亚、伊拉克、古巴、苏俄、尤里），允许留空；手填国家随登记保存并在审核、回执和公开详情展示，导入国家锁定并签名校验。人工填写的逐局记录不标记为已校验。

申请保存到现有EdgeOne项目的私有Blob命名空间 yuri-sponsored-matches，采用强一致读。每个申请独立保存，审核记录追加，不使用单个全局JSON覆盖；每申请独立的states对象保存权威审核状态，公开读取用强一致点读，不依赖可能延迟的审核日志列表。发布索引仅作查找，每次公开读取均检查最新审核结果。采集状态和每小时静态部署均不覆盖此存储。公开接口不返回待审/驳回资料、回执散列、审核原因或来源验签值；仅站主、持有对应回执的申请人及关联账号本人可读取各自许可内容。

### 站主登录

首次发布时，scripts/provision-sponsors.mjs 在可信GitHub运行器中为现有项目生成随机审核密码，保存为EdgeOne项目环境变量 SPONSOR_ADMIN_PASSWORD。已存在时保留原值；密码不写入仓库、日志或上传包。

请在现有EdgeOne项目的「项目设置 / 环境变量」查看该值，然后在网站「赞助赛 → 站主审核」登录。只有持有该密码的人可查看待审队列、通过、驳回或撤回已公开赛事；驳回/撤回须填原因。密码不存浏览器localStorage，登录使用8小时HttpOnly、Secure、SameSite=Strict签名Cookie。需要换密码时，由站主在控制台改为至少24字符随机密码并重新部署；原会话和旧的未提交来源验签会失效，后者需重新导入。

### 申请回执与防护

回执含申请编号和随机查询密钥。浏览器在发起请求前保留回执，可在网络中断后查询；提交重试不会覆盖既有申请。服务器仅保存密钥SHA256散列。回执可复制后在其他设备的「我的回执」粘贴查询状态及驳回原因，不允许修改或审核。请勿公开回执。

提交与审核强制同源JSON请求、24KiB正文限制、服务端字段/比分核验。提交使用20分钟签名验证、最短2秒等待和蜜罐字段；提交、来源导入及登录有持久化的尽力限流。对象存储不提供事务或原子比较交换，因此限流不是严格的分布式计数，审核版本检查用于防止常见的过期页面覆盖；仅一个站主审核，所有决定追加保存。未开通审核密码时，申请和审核均关闭。

本地预览使用 .runtime/sponsors-preview 文件存储，与生产完全隔离。须自行在本地进程设置 SPONSOR_ADMIN_PASSWORD（至少24字符）才能测试申请与审核；没有默认生产密码。停止并重新启动预览后记录仍保留。云端部署后，verify-sponsors.mjs 检查正式站公开列表和拒绝访客审核，并在独立私有验收命名空间验证真实存储重读、来源导入、通过/撤回，不创建虚假公开赛事。新增13项资料/权限/来源/回放链接/边缘请求正文测试，以及2项编译产物去除凭据测试。

API：GET /api/sponsors?action=list|session|challenge；GET action=queue（站主）；POST action=submit|receipt|import|login|logout|review。详情使用 GET action=list&id=<编号>；分页使用返回的cursor。列表按登记先后加载，每页最多30条，搜索与状态过滤作用于已加载记录，可继续加载；网址用screen=sponsors、sponsorTab=apply/mine/review、sponsorId恢复视图。统计筛选保留但不影响赞助赛。

## 选手对手档案与积分排名历史

选手研究中点击一位选手，可切换“对手档案”和“积分与排名历史”。对手档案继承当前赛季、时间、地图、己方/对手积分、分差和榜内范围筛选；按对手ID聚合，列出己方视角胜负、胜率、Wilson区间、最新交手时间及本次榜单积分。相近分数为绝对分差≤100，其他已知分差分为高分/低分；未知积分单列。支持搜索和排序，点击对手打开同一完整批次的比赛明细与己方三阵营交手统计。CSV增加对手档案和分组计数，最低样本门槛不改变档案统计。

积分与排名历史按每次完整榜单的真实采集时间记录，通过独立ranking_history表及带SHA256校验的断点文件长期保存；完整比赛快照轮换不会删除轻量历史。升级时复用可验证的完整公开快照及数据库中已有完整榜单；初始导入样本没有可靠榜单采集时间，因此不伪装成新观察点。只展示实际保存过的观察，不推算更早积分。

未选择个人时，选手研究页提供历史选手目录、最近两次完整榜单的入榜/离榜变化，以及当前浏览器收藏选手的快捷入口。掉榜选手仍可通过historyPlayer选择并查看旧记录；观察不到更低名次，因此不会填成第101名。GET /api/history?season=31&summary=1返回已记录选手目录和相邻榜单变化。

历史图支持积分/名次、全部/7天/30天、键盘定位及独立CSV导出。缺采超过3小时或未在该次榜单中时断线；未入榜显示空值，不记为第101名。历史仅受赛季、选手、historyRange影响，比赛筛选不改变历史曲线。周期从榜单实际观察时间倒推；已结束赛季也使用实际采集时间，明确说明采集可能在赛季结束后。它不改变比赛统计中的榜单快照积分口径。

### 原有数据接口

保留搜索、排序、个人统计、三阵营/十国矩阵、赛季/7天/30天、榜内对手、CSV和分享URL。前端从本站同源JSON计算，不请求旧chatgpt.site后端；可选头像和原始记录链接来自官方平台。

只读边缘接口：

```text
GET /api/stats?season=31&range=7d&opponents=top100&group=country&player=945674
GET /api/matches?season=31&group=faction&own=allied&enemy=yuri&offset=0
```

参数：season；range=season/7d/30d；opponents=all/top100；group=faction/country；player为字符串ID；map为来源地图原名；segment为下述积分或排名分段key。stats另接受compare（最多4个以逗号分隔的字符串ID）、bucket=day/week。view=compare/maps/trend/tiers与tierBy=mmr/rank用于保存界面视图。明细额外接受own/enemy、offset与snapshot。每页30行。矩阵明细按选手视角计出场数；独立比赛按ID去重；胜率=胜/(胜+负)。原始快照保留流局用于核查，查询与导出均排除。

内容文件名为完整SHA256；清单最后原子替换。保留前两次旧快照供已打开页面读取。边缘接口只读取本站静态数据，拒绝POST；无公开sync/MCP/admin写入口。

## 新增分析功能

- 选手对比：同时选择2至4位选手，比较总胜率及三阵营表现，并按两人组合展示真实直接交手比分。同一场比赛只从每对选手中第一位的视角计一次。比较遵循赛季、时间、地图、对手范围和分段筛选，不受个人详情选择影响。
- 地图胜率：按官方原始地图名称及版本分组，显示独立比赛、出场次数、总胜率与各阵营胜率；支持搜索、排序和点击地图筛选全站。不会擅自合并不同版本地图。
- 近期走势：按北京时间自然日或周一开始的自然周统计，遵循顶部时间窗口。展示分期胜率而非累计胜率；空白日期没有样本，显示“—”并断开折线。支持阵营切换、鼠标或键盘读取点位和完整数据表。
- 收藏选手：榜单星标及个人页均可收藏，支持只看收藏。按字符串ID保存在当前浏览器localStorage，跨赛季保留、同一浏览器标签间同步；不登录，不跨设备同步。存储不可用时本次页面内可继续操作并提示。
- 分段阵营胜率：积分分为2000以下、2000–2999、3000–3999、4000及以上；排名分为1–10、11–25、26–50、51–100。以本次榜单快照的己方选手积分/排名分组，统计该组前100名选手的赛季胜负记录，不是比赛时历史积分，也不代表全平台。各分段横向比较遵循时间、地图与对手筛选，不受个人详情或单个分段选择影响。点击分段筛选榜单、个人矩阵和明细。

少于20局标记样本较少，零样本胜率为null/“—”。榜内双方各计一次出场；地图/分段的独立比赛按字符串比赛ID去重，不同分段的独立比赛数不能相加。CSV同时导出地图、走势、对比和分段，带统计口径、截止时间及当前筛选。分享URL保留选手、地图、分段、对比列表、走势周期和分析标签。

GET /api/stats?season=31&segment=mmr%3A4000%2B

## 精细积分与分差筛选

“精细筛选”支持己方、对手的任意积分上下限，绝对分差上下限，以及只看更高分/更低分对手。上下限包含边界，可只填一侧；留空不限，0是有效条件，例如分差0–0表示同分。按“应用筛选”才生效，错误区间保留上次结果并显示提示。快捷方案提供同水平≤100、分差≤200、挑战高分≤300、观察低分≤300。

所有积分来自本次赛季榜单快照，不是比赛发生时的历史积分。现有数据仅含前100名积分；开启对手积分或分差条件后，缺少所需积分的出场会被排除，不会当成0分。覆盖率按当前己方范围/个人统计，显示筛选前出场、符合条件、双方积分已知比例、未知积分排除数及已知积分不符条件数。覆盖率分母包括当前时间/地图/榜内范围，独立比赛仍按ID去重。

榜单、个人矩阵、地图、走势、对比、比赛明细和CSV共用同一积分/分差筛选。分段横向比较忽略单个己方分段与自定义己方积分范围，继续遵循时间、地图、对手范围、对手积分和分差条件。UI切换固定分段会清除自定义己方范围，应用新的自定义己方范围会清除固定分段与个人/比较选择；直接API同时传入则取交集。

最低样本数仅影响榜单和地图列表，不改变总体胜率、矩阵或走势。榜单按当前排序指标样本数筛选（例如按盟军胜率排序时看盟军场次），地图按总场次。CSV只导出当前可见选手及达到门槛的地图，保留全部矩阵/走势及筛选条件。新增Wilson 95%置信区间，描述样本不确定性，不保证未来表现；零样本无区间。

API新参数：mmrMin/mmrMax（己方）、enemyMmrMin/enemyMmrMax（对手）、gapMin/gapMax（绝对分差），均为0–100000整数；gapDirection=any/stronger/weaker；minSamples=0–10000整数。非法数值或反向区间返回400。比赛明细新增ownMmr/opponentMmr和scoreGap，后者为对手积分减己方积分，带正负号；ratingBasis为ladder-snapshot。

```text
GET /api/stats?mmrMin=3500&mmrMax=4300&gapMin=0&gapMax=100&minSamples=20
GET /api/stats?enemyMmrMin=4000&gapMax=300&gapDirection=stronger
GET /api/matches?mmrMin=3500&mmrMax=4300&gapMax=100
```

使用`node scripts/verify-rating-data.mjs dist/data`可逐场独立复核两个赛季、三个时间窗口、两种对手范围、七组积分条件，旧版100人名单共126组合；两个赛季全榜完成后，前100与全榜两种名单共252组合。
